# 書き出し仕様（spec.json・ビルド・Figma・CMS入稿シート）

## 1. spec.json

案件ごとに1ファイル。紹介者ページとゲストページはペアで同じファイルに入れる。記入例は `assets/sample_spec.json`。

```json
{
  "project": "案件名（ファイル名にも使う）",
  "theme": {"mode": "wire"},
  "offer": {"inviter": "紹介者の特典", "guest": "ゲストの特典"},
  "pages": [
    {
      "pageType": "inviter",
      "title": "ページタイトル（フッターの表示名の既定値）",
      "blocks": [
        {"type": "benefits", "state": "mod", "note": "このブロックで伝える1点",
         "data": {"title": "ご紹介で\nおふたりに特典", "a": "500円OFF", "b": "20%OFF", "note": "※条件"},
         "images": {"ico1": "assets/icon_a.png"}}
      ]
    }
  ],
  "outOfCms": ["CMSのパーツでは実現できない要望"]
}
```

| キー | 内容 |
|---|---|
| `type` | `03-cms-blocks.md` の type。カタログに無い値はエラーで止まる |
| `state` | `keep` / `mod` / `new` / `plain`。入稿シートとプレビューの表にだけ出る（デザインには描かない） |
| `note` | このブロックで伝える1点・修正意図。入稿シートの「意図」列になる |
| `data` | 入力項目。書かなかった項目はカタログの初期値が入る。カタログに無い項目は警告して無視 |
| `images` | 画像枠のスロット名 → 画像ファイルのパス（spec.json からの相対）。無い枠は比率つきの枠で描く |
| `minH` | 任意。ブロックの最低の高さ（pt）。余白を広げたいときだけ使う |

項目の形：
- 箇条書き・行・ステップ（`bullets` / `rows` / `steps`）は文字列の配列
- アコーディオン・FAQ（`items`）は `{"q": "見出し", "a": "開いた中身"}` の配列
- スライダー（`slides`）は `{"text": "説明文", "btn": "任意のボタン文言"}` の配列
- 画像スロットの `{i}` は0始まりの連番（`s0`, `s1`…、`st0`…、`r0`…）

**配色**
- ワイヤー（既定）：`{"mode": "wire"}`。無彩色
- ブランド：`{"mode": "brand", "primary": "#E4007F", "accent": "#E4007F"}`。変えられるキーは `primary`（ボタン・バナー・ステップ番号の地色）、`onPrimary`（その上の文字色）、`accent`（Q/A 記号）、`ink`、`body`、`sub`、`line`、`bg`、`footer`、`onFooter`、`radius`（ボタンの角丸 pt）、`font`、`headFont`
- LINE ボタンの緑、必須バッジの赤は CMS 固定の色として変えない
- **CMS の管理画面でどこの色を変えられるかは要確認。** ブランド配色で作るときは、CMS で再現できない色の当て方をしていないか【7】で確認事項にする

## 2. ビルド

```bash
python3 scripts/build.py <spec.json> [--out <出力フォルダ>] [--scale 3] [--zip]
```

標準ライブラリだけで動く（追加インストール不要）。出力は既定で spec.json と同じ階層の `out/`。

| ファイル | 用途 |
|---|---|
| `<案件>_紹介者ページ_figma.svg` など | ページ単体の Figma 用 SVG（幅1125px） |
| `<案件>_figma_all.svg` | 全ページを横並びにした SVG（ペアで渡すとき） |
| `<案件>_cms_sheet.md` | CMS 入稿シート（読む用） |
| `<案件>_cms_sheet.csv` | 同じ内容の表（スプレッドシート・Excel 用。BOM 付き UTF-8） |
| `<案件>_preview.html` | 壁打ち用プレビュー（デザイン＋構成表＋要確認の一覧） |
| `<案件>_handoff.zip` | `--zip` 指定時。上記一式＋spec.json |

**要確認（警告）の種類**
- はみ出し：1行が枠を超えている → 文言を短くする
- 見出しの泣き別れ：最後の行が1〜2文字 → `\n` で改行位置を指定するか文言を変える
- CTA の遷移先・計測方法が未確定 → 【4】の三点セットを埋める。埋まらなければハンドオフへ
- 画像が見つからない：`images` のパスが間違っている

## 3. Figma への取り込み

- **SVG ファイルを Figma のキャンバスにドラッグ＆ドロップ**する（または SVG の中身をコピーしてキャンバスに貼り付け）
- ブロックごとに `01_ヘッダー（ロゴ＋ボタン）` のような名前のグループになる。その中に `見出し`・`本文`・`ボタン_背景`・`ボタン_文言`・`画像枠_◯◯` などの名前付きレイヤーが入る
- 文字はテキストレイヤー、矩形はシェイプ、支給画像は画像として展開される。改行位置は確定済みで、1行ずつ位置が固定されている
- フォントは Noto Sans JP（本文）と Zen Kaku Gothic New（見出し）。どちらも Google Fonts で Figma から使える
- 幅は1125px（375pt × 3）。375 幅のフレームで作業するデザイナーには「25% に縮小して配置」と伝える（`--scale 1` で 375px 幅の SVG も出せる）

Figma 上での見え方（テキストレイヤーのまとまり方など）は Figma のバージョンで変わりうる。取り込み後に崩れを見つけたら、レンダラー側で直す。

## 4. CMS 入稿シート

ブロック順に、CMS で選ぶパーツと入力内容をまとめたもの。CS 担当・入稿担当はこれを見ながら CMS に入れる。

- 冒頭の表：No／CMSパーツ／CMSクラス（`invyBlockEditor-*`）／状態／意図
- ブロックごと：入力項目と内容、画像枠（支給ファイル名または「未支給」、比率）
- 末尾：CMS外の要望

**画像サイズについて**：シートに出るのはレンダラー上の比率（pt と ×3 の px）。CMS 側の推奨入稿サイズは未確認なので、入稿前に確認する。

## 5. カタログを直すとき

ブロックの追加・項目の変更は `scripts/catalog.py` を直し、描画を `scripts/render.py` の `SHAPES` に足す。
直したら `python3 scripts/catalog.py --md > references/03-cms-blocks.md` で参照を再生成し、
`python3 scripts/build.py assets/sample_spec.json` で壊れていないか確認する。
