# 3つの流れ

## 共通の準備（毎回）

1. CMS 制約表を読む：`references/config.json` の `constraintsSheetId` を Google Drive の
   `download_file_content`（`exportMimeType: "text/csv"`）で CSV として取り出し、
   `python3 scripts/constraints.py load <csv> > <案件>/constraints.json` で変換する。
   Drive が使えないときは制約チェックなしで進め、そのことを伝える
2. `blocks/CATALOG.md` を読み、使えるブロックを把握する。迷ったら `blocks/shots/<id>.png` を見る

---

## ① 構成案の自動組み上げ

**入力**：クライアント名・業種、ページ種別（紹介者／ゲスト／両方）、特典、伝えたいこと、既存ページ（あれば）。
足りない情報は一度にまとめて聞く（多くても5問）。答えが無いものは仮説で置き、仮説だと明記する。

1. **ページの役割を1文で決める**（紹介者ページ＝紹介者に何をしてもらうか／ゲストページ＝何をしてもらうか）
2. **ブロックを選んで並べる**：CATALOG.md から、目的に合うブロックとバリエーションを選ぶ
   - 定石：ヘッダー → KV（`image`）→ 特典 → 紹介の流れ → （ヒント・口コミなど）→ 紹介フォーム →
     FAQ → 必ずお読みください → フッター → フローティングバナー
   - 同じ役割で複数のバリエーションがあるときは、内容の量（繰り返しの個数・画像の有無）で選ぶ
   - 制約表に「使えるページ」があれば守る
3. **文言を入れる**：各ブロックの入力項目を埋め、繰り返しの個数を決める（`02-copy-rules.md`）
4. **page.json を書き、`compose.py --wire` で構成案 HTML を出す**。警告（制約違反・存在しない項目）をゼロにする
5. **構成表と構成案 HTML を見せて、ここで止まる**。構成表は「No／ブロック ID／ブロック名／このブロックで伝える1点」

## ② デザインの作成

①の構成が承認されてから行う（構成案なしで「デザインして」と言われたら、①から始める）。

1. **全体の雰囲気を決める**：クライアントのブランド（ロゴ・サイト・既存ページ）から
   - Main（ボタン・強調）と Sub（アクセント・ページ送り・帯）の2色
   - フォントのモード：`gothic-regular` / `gothic-light` / `mincho-regular` / `mincho-light`
     （上品・高級感なら明朝、親しみ・分かりやすさならゴシック。迷ったら `gothic-regular`）
2. **グレーの画像枠を埋める**：支給素材を `images` に割り当てる。足りない画像は「どの枠に・何の画像を・推奨サイズ」で一覧にして依頼する
3. `compose.py`（`--wire` なし）でデザイン HTML を出して見せる
4. **合意できたら Figma に書き出す**（`figma-write.md`）。Figma コネクタが無い・切れているときは HTML を渡して、再接続を案内する

## ③ デザイン修正

1. **最初の返答で止まる**：「元のデザインを教えてください。Google Drive などに置いてある場合は、その場所（URL）を教えてください」とだけ返す。
   この時点で修正案を出さない
2. **読み込む**：教えてもらった場所から元のデザインを読む
   - Google Drive の画像（PNG／JPG）・PDF：`download_file_content` で取り出して画像として見る。縦に長い画像は分割して読む
   - このスキルが出した HTML や page.json：そのまま読む
   - Figma の URL：Figma コネクタで `get_screenshot` / `get_metadata`
3. **HTML に起こし直す**：元のデザインを、ブロック庫のどのブロック（どのバリエーション）の組み合わせかに分解し、
   文言・色・フォント・画像を page.json に写す。ブロック庫に当てはまらない部分があれば、その旨を伝える
4. **起こし直したものを見せて確認する**：「元のデザインをこう読み取りました」と HTML（と構成表）を見せ、ずれがないか確認してもらう
5. **指示どおりに修正する**：page.json を直して `compose.py` を流す。変更点を2〜3行で伝える
6. **Figma に書き出す**（`figma-write.md`）。元の Figma があれば、別ページに書き出して並べて比べられるようにする

---

## 渡すときに添えるもの

- 構成表（No／ブロック ID／ブロック名／伝える1点）
- 未確定事項（遷移先 URL、特典の条件、計測方法など）
- 画像の依頼リスト（枠・内容・推奨サイズ）
- CMS外の要望（ブロック庫で実現できないもの）
